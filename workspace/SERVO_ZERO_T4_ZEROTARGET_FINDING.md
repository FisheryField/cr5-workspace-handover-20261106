# T4 专项结论：驱动器收到「0x607A = 0」时两版分别做什么

> 来源：子代理 `30b8012b`（2026-09-26，有界任务，≤25 次工具调用）
> 工具：`tools/z_607a_scan.py`、`tools/z_tool.py`（capstone 线性解码 + skipdata）
> **地址约定：真·flash 地址 = ELF vaddr + 0x10000**（Ghidra 工程坐标 = vaddr，比真值低 0x10000）

## 1【逐条读码证实】两版都**没有**"0x607A == 0 ⇒ 特殊处理"的代码路径

- 全镜像解码指令数：**D8 = 151,248 条 / 3150 = 148,648 条**
- 以字面偏移访问 0x607A 字段 `[+0x24C]` 的指令：**D8 = 0 条，3150 = 0 条**（已过滤 PC/SP 相对口径）
- 常量 `0x24C` 只作立即数出现 **1 次/版**，都在 OD 分派器 handler：
  `D8 true 0801315A` / `3150 true 08013076`，形态
  `movw r3,#0x329 ; muls r3,r2,r3 ; ldr r4,=<0x2000138C|0x2000129C> ; add r3,r4 ; addw r3,r3,#0x24c ; str r3,[r0,#0x18]`

⇒ **0x607A 的值只能经"分派器运行时算出的字段地址"流动**，镜像里不存在第二个使用点
⇒ **不可能有以 0x607A 为判据的分支** ✓

## 2【逐条读码证实】两版都**没有**把 0（或任何常量）写进 0x6064 / 0x6063 / 0x6062

| 对象 | 写点（真地址） | 形态 |
|---|---|---|
| `+0x238`（0x6064） | D8 `08025602` `str.w r1,[r0,#0x238]`（fn `08025398`）；3150 `08024B62` `str.w r0,[sb,#0x238]`（fn `08024864`） | 两者前一条都是 `blx` 到函数指针表 `[+8]` |
| `+0x234` | D8 `080255EC`；3150 `08024B04` | 都是算式 |
| `+0x230`（0x6062） | D8 `08030C38`/`08030D58`；3150 `0802F87C`/`0802F98A` | 都是 `fp(...)` |

⇒ **"把 0x6064 重新定基到 0"在本固件里不是一条赋值语句** ✓

## 3【逐条读码证实】0x6062 生产块两版逐条同构（只差已知 RAM 重排）

- D8 `08030C1E-C38`：`ldr.w r0,[sb,#0x14]` / `ldr.w r1,[r4,#0xb0]` / `add r1,r0` / `str.w r1,[r6,#0x26a]` / `ldr r2,[r0,#8]` / `blx r2` / `str.w r0,[r6,#0x230]`
- 3150 `0802F862-F87C`：同形态，仅 `[r4,#0xb0]`→`[r4,#0xa0]`（运行期数组整体 −0x10，已知）

⇒ **上报/需求路径不是差异点** ✓

## 4【逐条读码证实】0x6064 生产算式两版**结构性不同**（差异真正所在）

调用者拓扑两版一致：写 `+0x238` 的函数 ← `bl`（宿主 = 含 0x6062 写的 CiA402 状态机函数）；
另有读 `+0x238` 与另一个函数，同属另一个宿主（逐轴周期函数）。

| 项 | D8 `08025592-08025602` | 3150 `08024A8A-08024B62` |
|---|---|---|
| 门控 | `movs r0,#0xcc; ldr r0,[r0,r5]` | `movs r0,#0xb4; ldr r0,[r0,r4]` |
| 归一化 | **立即数**：`#0x20000`(0802559E)、`#0x4e20`=20000(080255A6)、除数 `#0x20000`(080255BE) | **变量**：`[r4]`(08024A96)、`[r4,#0xc]`(08024A9C)、`[..,#0x22c]`(08024AA4)、除数 `[r4]`(08024ABC) |
| 结果存放 | `str.w r6,[r4,#0xb0]` | `str.w r6,[r5,#0xa8]` |
| 0 比较 | **无** | **有**：`08024B0C cmp r0,#0` / `blt`（负数借位支） |
| 全局状态 | **无** | `08024AE4 strb 1` / `08024AEA cmp #1` / `08024AF2 str 0,[..+0x18]`（清 `0x20003DB0+0x18`） |
| `+0x234` | `= +0xB0 + [sp+0x18]+0x10` | `= +0xA8 + [sp+0x14]+0x10 + [0x20013DB0+0x18]` |
| 尾部 | 直接 `fp(+0x234) → +0x238` | 先 `sdiv/mls` 写商/余数到 `0x20013DB0+4/+0`，再 `fp(+0x234) → +0x238` |

## 5【顺序推断，非逐条读码】`+0x234` = **0x6063**（位置实际值·内部单位）

依据：两版在 `true 08012xxx` 段各有 **96 个 OD handler 偏移，逐项且顺序完全相同**
（`+0x230` @ D8 `08012BA2` / 3150 `08012ABE`；`+0x234` @ `08012BB4` / `08012AD0`；`+0x238` @ `08012BC6` / `08012AE2`，三槽连号）
⇒ 已知 `0x6062→+0x230`、`0x6064→+0x238`，中间恰一槽 ⇒ **`0x6063→+0x234`**
⇒ 于是 `+0x238 = fp(+0x234)` = **内部单位 → 用户单位的换算**，与"经函数指针 `[+8]` 换算"吻合 ✓

附带：`+0xA8/+0xB0/+0x36` **无 handler ⇒ 不是 OD 对象**；
`+0x2B3..+0x2F9` 有约 **20 个连号 handler ⇒ 厂商 H 参数就活在这一段** ✓（新线索）

## 6【候选 · 机制解释】"回零"差异是**参考系差异**，不需要也没有特判

- 目标（0x607A）与实际（0x6062/0x6063/0x6064）**共用同一个 `fp()` / 同一参考系**；
- **3150 的 `0x6063` = 编码器原始绝对计数**（现场 J6 = 20.5046° = 115,054 counts ≈ `innerEncoder` 115,043 ✓）
  ⇒ "目标 0" = 原始计数 0 = 几十度之外 ⇒ **手臂真的被开过去**；
- **D8 的 `0x6063/0x6064` 已减去一个参考量** ⇒ "目标 0" = 当前零点姿态 ⇒ **不动、零点就地成立**；
- 该参考量**掉电不丢** ⇒ 不在位置链（位置链无零偏变量）⇒ **最可能落在编码器 preset / 厂商参数层** ✓

## 7【未证实 · 还缺什么】

1. **0x607A 的消费点**：值只经分派器算出的字段地址流动 ⇒ 需 RAM 转储里的 PDO 目标地址表，
   或在 `D8 true 0801315A` / `3150 true 08013076` 的 `str r3,[r0,#0x18]` 下断点。
2. **单次即可判定的实验** ✓✓：同一姿态分别读两版 **SDO `0x6063` / `0x6062` / `0x6064`**：
   - 若 **`0x6063` 两版相同、`0x6064` 不同** ⇒ 差异在 **`fp()`**（表 D8 `0x20000078` / 3150 `0x20000074` 的 `+8` 槽；该表**全镜像零写入站点** ⇒ 必须运行期看）；
   - 若 **`0x6063` 本身就不同** ⇒ 差异在**编码器读入 / preset 层**。
3. **把 `H01.17 / H0C.02 / H01.18` ↔ `+0x2B3..+0x2F9` 对上**（`tools/od_table.py` 的名字表与这 96 个 handler 按顺序对齐），再找这些字段的消费者
   ⇒ **若"校零"由写某个 H 参数触发，那条路远比改固件安全** ✓

## 对"把 D8 数值机制移植到 3.1.5.0"的意义

- **没有单一的"定基赋值"可以搬** ✗ —— 差异是**参考系/参考量**，而它在**编码器 preset / 厂商参数层**（位置链无零偏变量）；
- **可搬的候选**只有 §4 那张表里的**结构性算式差异**（`+0x234`/`0x6063` 的构造），但它是**变量 vs 立即数 + 商余数状态机**的整套差异 ✗（不是几个字节的补丁）；
- ⇒ **最优先的两条**：① §7.2 的**单次 SDO 对照**（定出差异在 `fp()` 还是编码器层）；② §7.3 的**参数映射**（若"校零"由写 H 参数触发 ⇒ 走参数而非固件 ✓）。
