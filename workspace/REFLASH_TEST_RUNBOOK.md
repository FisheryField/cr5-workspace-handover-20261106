## 0. 为什么必须做这一步

| 事实 | 状态 |
|---|---|
| 自制 3.1.5.0 包**逐字节正确**（payload MD5 与头内记录一致、完整镜像 SHA-256 可核） | ✅ 已离线验证 |

## 1. 前置条件（动手前逐条确认）

| # | 条件 | 怎么确认 |
|---|---|---|
| 1 | 控制箱在线、SSH 可用 | `ssh root@192.168.5.1 "echo ok"` |
| 2 | **机器人已下使能**（无运动、无程序运行） | 示教器/上位机确认 |
| 3 | **J6 仍是 3.1.5.0**（我们唯一可用的轴，也是本次目标） | 见 §2 步骤 2 |
| 4 | **电源稳定**（刷写中断电 = 变砖，这是唯一真风险） | 别用不稳的插座/UPS 切换 |
| 5 | 回退件在手边 | `data/servo_fw_samples/CR5_Servo_ST_FOE_V3.1.5.0_UNVERIFIED.bin` |

### ⛔ 本次的目标轴 = **J6（slave 8）**

理由：J1–J5 是 D8（用户确认**不能用于运动**），**J6 是唯一还能干活的轴**。
所以本次只动 J6，其余五轴不碰。

⚠️ **但要注意**：如果 J6 刷坏，整台机器就没有可用轴了。
这是本次实验的**固有风险**，必须在动手前认可。

## 4. ★ 刷 J6，并抓取**结果行**（本次唯一判据）

刷写触发后，**立刻**用下面这条抓日志（**不要加 `tail`**）：

```bash
ssh root@192.168.5.1 "grep -a -nE 'dobot_foe|foe write|TempFoeWriteErrCode' \
  /dobot/userdata/CR5_sys_files/project/logs/all/log"
```

### 判据（最重要的一步）

| 看到什么 | 判定 | 下一步 |
|---|---|---|
| `foe write result is success. g_TempFoeWriteErrCode=0` | ✅ **包被接受** | 继续 §5 |
| `foe write result is fail` / `errCode != 0` | ❌ **包被拒绝** | **停手**，不要改固件 |
| 只有 `start FoE write....` 就没了 | ⚠️ 未定论 | 等 30 s 再抓一次；仍无结果 ⇒ 视为失败 |

预期时序（参考 9/16 那次成功记录）：
```
11:10:37  start FoE write...., filesize=338104
11:10:42  foe write result is success. g_TempFoeWriteErrCode=0     ← 约 5 秒
```

## 5. 整柜断电重启（**必须物理断电，不是重启控制器**）

## 6. 重启后验证（三条）

```bash
# ① 版本：J6 应仍是 3.1.5.0（内容相同，所以版本不会变 —— 这只能证明"没变坏"）
grep -a -A14 "settVersion" /dobot/userdata/CR5_sys_files/project/logs/all/log | tail -20

# ② 伺服有无故障码
grep -a "logServoError" /dobot/userdata/CR5_sys_files/project/logs/all/log | tail -8

# ③ 零点记录有没有被清（应与 §2 步骤 2 一致）
cat /dobot/userdata/project/settings/function/homeEncoder.json
```

### 判据

| 检查 | 通过 | 失败 |
|---|---|---|
| servo6 = 3.1.5.0 | ✅ | ❌ 版本变了 ⇒ 异常，停手 |
| 无新增 servo 故障码 | ✅ | ❌ 有故障 ⇒ 停手 |
| `homeEncoder.json` 与刷前一致 | ✅ | ⚠️ 变了 ⇒ 记录，先别继续 |

## 7. ★ 功能验证（**这一步才是真正的"能回退"证明**）

仅仅"上电了"不够 —— 要证明**这个轴还能正常干活**：

1. **上使能**
2. **等机械臂完全静止 ≥30 s**
3. **点"零点标定"**
4. 读数应 **≈ 0**（与刷前行为一致）
5. **下使能 → 上使能 → 再等完全静止**
6. 读数应 **≈ 2.9°**（**与刷前同样的老毛病** —— 这是正常的，因为固件内容没变）

> **判据：J6 的行为应与刷写前**完全一致**（同样"标定能归零、重上使能弹回"）。
> 如果行为一致 ⇒ **写通路 + 回退能力都验证通过** ⇒ 可以进入下一步（打补丁）。

## 9. 失败处置

| 情况 | 处置 |
|---|---|
| FoE 报 fail | 什么都不用做，重新刷一次原版包即可（内容相同） |
| 刷完 J6 起不来/有故障 | 用**同一个包**再刷一次（内容与机上原版相同），若仍不行 ⇒ 该包不可用，**永久停手改固件路线** |
| 版本变成非 3.1.5.0 | 记录实际版本，停手分析 |
| **刷写中断电** | 重新上电后用原版包重刷（bootloader 在 `0x08000000~0x08002897`，FoE 不覆盖，应可恢复） |

⚠️ **唯一会变砖的情形**：刷写**过程中**断电导致应用区半写。
bootloader 独立于 FoE 应用区，所以**理论上仍可重刷恢复** —— 但这是理论，没实测过。

## 10. 通过之后

如果 §7 全部一致 ⇒ 恢复链空白补上，可以进入第二步。

> ⛔⛔ **不要用 §10 原文里那条命令生成补丁 —— 那一版补丁的字节是错的。**
> 原文写 `python tools/servo_patch_3150.py --apply` + `servo_patch_verify2.py`；
> 补丁脚本的 `PATCH_NEW` 曾经是 `08 46`（= `mov r0,r1`，**方向反了**），
> 它会把 `+0x234` 变成**只剩修正项**。详见 `SERVO_SUMMARY.md` §13.2。
> **现在必须用下面这套命令与哈希。**

```bash
# ① 生成补丁包（脚本默认 dry-run，先看它自己的反汇编闸门输出）
python tools/servo_patch_3150.py                       # 变体 A（主用）：先干跑
python tools/servo_patch_3150.py --apply               # 确认无误再落地
python tools/servo_patch_3150.py --variant B --apply   # 可选：1 字节的最小改动版

# ② 权威验证器：34 条断言，必须全部 PASS 才能用
python tools/servo_patch_verify3.py
```

**落地后必须核对哈希**（与 `SERVO_SUMMARY.md` §13.5 一致，不一致就不要刷）：

| 文件 | MD5 | SHA-256 |
|---|---|---|
| `servo_fw/CR5_Servo_ST_FOE_V3.1.5.0_PATCHED_no_correction.bin`（变体 A） | `42bd7a9f6b8166154eac379c47780d5d` | `096803ab92b795cec242e8aa5a76ed4df12bcd360e79ec9d77b46d65b6c33897` |
| `servo_fw/…_no_correction_min1byte.bin`（变体 B） | `0aaf60bb85a72963f09a3335d59b5dc5` | `5de751db56d821c0cebc30c922916c0db1d1a5a03b2e344dfa4ab4844169924b` |

**A 与 B 的差别**：A 把 `+0x18` 那一项**整条删掉**（6 字节：`mov r1,r0` + 两个 NOP）；
B 只把 `add r1,r0` 改成 `mov r1,r0`（**1 个字节**，`44`→`46`），保留两条"读了不用"的指令。
**两者最终 r1 完全相同**（都 = `基准 + 归一化`，即 3.2.D.8 的值）。
**若要极限降低改动量，用 B；若要对齐 D8 的代码形态，用 A。**

然后**同样只刷 J6**，观察：
- 标定 → 归零 ✅
- **下/上使能 → 是否还弹回 2.9°** ← **这一条就是判据**

⚠️ 这一步**才开始有"改坏"的可能**（内容与机上不同了）。但仍然：bootloader 独立、原版包在手，可回退。

### 补丁测试时的额外注意

1. **刷前先确认上传到控制器的是哪个变体**（文件名不同，别拿错）。
2. 刷完**整柜断电重启**后才生效（与 §5 相同）。
3. 断电重启后先看**版本号仍是 3.1.5.0**（补丁不改版本字）＋ **无伺服故障码**，再做标定动作。
4. **判据是"重新上使能后 J6 读数是否还弹回 ~2.9°"**：
   - 不弹回（≲0.1°）⇒ 补丁有效，记录，然后考虑推到其余轴。
   - 仍弹回 ⇒ 补丁无效（假说被否证）⇒ **回刷原版** `CR5_Servo_ST_FOE_V3.1.5.0_UNVERIFIED.bin`，
     并把结果回填到 `SERVO_SUMMARY.md` §13.6 —— **这也是有价值的结论**（能排除掉最强的那条差异线索）。
   - 出现故障码 / 轴不动 ⇒ 立即回刷原版。
5. **一次只动一个轴**（J6），确认有效后再逐轴推进；**不要一次刷六个**。
