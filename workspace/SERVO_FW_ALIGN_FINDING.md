# 伺服固件两版对齐 —— 结论（2026-09-23）

> 回答"先走 2：定位那块 21.48% 的同源代码"。**结论：那块是假的；两版之间不存在值得 diff 的同源代码。**

---

## 1. 路线 2 的结果：❌ 假热点（自我推翻）

按计划定位高相似度区域，最初看起来极有戏：

```
0x08000200   100.00%     <- 向量表 / 启动代码
0x08000400    99.41%
0x08028000    72.66%     <- "最热的代码块"
0x08028200    54.30%
0x08027a00    53.12%
```

但**并排反汇编一看就露了**：

```
NEW 3.2.D.8                  | OLD 3.1.5.0
*0x08028000 movs r0, r0       | 0x08028000 strh r0, [r0]
*0x08028002 movs r0, r0       | 0x08028002 movs r0, r1
 0x08028004 movs r0, r0       | 0x08028004 movs r0, r0
*0x08028006 movs r0, r0       | 0x08028006 lsls r0, r1, #2
```

`movs r0, r0` = 半字 `0x0000` ⇒ **新镜像在那块是 80% 的 `0x00` 填充**，老镜像有真实代码。
**"72.66% 相同"是 0x00 字节对上少量相同字节的假象。**

### 1.1 排除填充后的重算（这才是真实数字）

```
非填充块数: 418
平均一致率 3.38%   中位 2.15%   最高 21.68%
最高的一块 0x08049c00 = 21.68%（仅 512 B，周边立刻掉到 ~14%）
```

**⇒ 两版之间没有任何"同源代码块"。** 峰值只有噪声上限级别，不足以做功能 diff。

### 1.2 我自己犯的错（记录以免重犯）

**跨固件比相似度必须排除填充字节。** 两版镜像各有约 16-17% 的 `0x00` 与大片稀疏区，
"同地址一致率"会被填充抬高数个数量级。
`tools/servo_hot.py` / `servo_map_diff.py` 的原始输出**在排除填充之前都不可用**。

## 2. 路线最终判定

| 问题 | 判定 | 依据 |
|---|---|---|
| 两版是同源代码库的两次构建？ | **否**（或差异极大） | 调用图指纹 1,233 → 仅 **5** 相交；同地址 4 KiB 块 **0 个**完全相同 |
| 有可做功能 diff 的共享代码块？ | **否** | 排除填充后平均 3.38%、中位 2.15%、峰值 21.68% 且孤立 |
| 词表为何几乎一致？ | 共用的 **CiA402 对象字典定义** | 205 条共同串；零点相关名串逐字相同 |
| **跨版本 diff 找"零点修复点"** | **不可行，建议彻底放弃** | 上述 |

两版**都是合法可运行镜像**（向量表、SP、Reset 均正常）⇒ 不是数据损坏，而是**两套不同实现**。
为何同型号伺服存在两套实现**未查明**（不同分支/工具链/硬件批次皆可能），但**不影响结论**：没有共享代码可 diff。

## 3. 修正后的下一步（唯一现实路线：单向逆向 3.2.D.8）

不再依赖两版对比，改为**在 3.2.D.8 里直接找"位置定基被持久化"的逻辑**。

### 3.1 已具备的抓手

* **对象字典词表已定位**：`'Home offset'`、`'Motor calibration date'`、`'Encoder increments'`、
  `'Position encoder resolution'`、`'Facturer_specified1/2'` 等 CiA402 人类可读名，
  **代码里必有引用它们的位置**。
* **向量表 + 调用图**：`tools/servo_recover.py`（619 函数）、`tools/servo_cg.py`（1,233 调用点）。
* **反汇编工具链**：`servo_cm.py`（定点反汇编）、`servo_cmp_region.py`（并排对比）、
  `mkelf.py`（→ 可导入 Ghidra 的带符号 ELF）。

### 3.2 具体第一步

1. 在 3.2.D.8 镜像里**搜出这些名字串的地址**，再找**引用它们的字面量池/指令**
   （`ldr rX,[pc,#n]` 且该字面量 = 名字串地址）⇒ 到达**对象字典表定义处**；
2. 从对象字典表反查 **`Home offset` / `Motor calibration date` 条目**，找**读写它们的代码**；
3. 重点看**谁把"定基结果"写进非易失存储**（flash 写入点 / 厂商参数的 store）。
   这一段最可能就是两版行为不同的位置。

> 这条路线**只需要 3.2.D.8 一个镜像**，不受"两版不可比"影响。

## 5. 诚实清单

**事实**：两版排除填充后中位一致率 2.15%；调用图 5/1233 相交；字符串表 205 条共同；
`0x08027600` 一带的"高相似"是填充假象（新镜像该处 80% 为 `0x00`）。

**推断**：两版是不同实现；词表来自共用 CiA402 定义。

**已作废的说法**：早期版本里"存在一块 21.48% 同源代码，值得优先阅读"——
**错误，已由并排反汇编推翻**；跨版本 diff 路线**判定不可行**。
