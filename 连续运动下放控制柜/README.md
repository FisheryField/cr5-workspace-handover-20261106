此前由RoboDK/PC逐段控制，改为将已规划路径写成控制柜Lua工程，由PC上传文件并通过RunScript启动控制柜本地执行。它减少PC逐段调度，并不等于已实现全轨迹无停顿融合。脚本仍含逐点检查、同步/到位逻辑。

## 如何接手

先读取工程src0.lua、启动器和预检记录，核对机械零位、TCP、本体、当前轨迹和场景。控制柜远端工程根目录历史为`/dobot/userdata/project/project`，命令口29999。启动器会上传文件并可能发送运动，不能作为只读检查直接运行。

这里的启动器是**原工作空间脚本副本**，WORKSPACE仍指向`D:\mydata\glm-workplace`，工程读取路径仍是其sim_scripts/rdk_station_dump/cr5_controller_deployment_check，凭据与SSH辅助工具依赖原tools/rssh.py。没有改成可在任意位置直接运行的安装包，也没有加入凭据。换机器时须人工审查路径、依赖与本地认证；不要直接从此归集目录双击启动。

启动前历史要求：机械臂在已确认的零位、RoboDK实机驱动断开、命令口无冲突、现场人员确认可运行。归集工程内记录的关节值只适用于当时模型/零点/几何，不能拿来直接适配另一台设备。

“轨迹输入”是归集时磁盘副本，不自动声称与历史预检哈希相同；预检适用范围以报告及工程哈希为准。11月5日工程和连续轨迹_11-5.json是另一组归档，不等同于本目录轨迹17。
