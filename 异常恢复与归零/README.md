# CR5 异常恢复与归零交接

整理日期：2026-11-06。适用对象为本仓库记录的这台Dobot CR5及其历史主控/伺服组合。本目录仅整理资料，未连接控制器、刷写、使能或执行运动。

## 先读：三个不同的“归零”

1. **机械回原点**：把六轴实际运动到正确机械零位，核对刻线/真实姿态。异常坐标显示为0，不代表机械已经对齐。
2. **软件标零**：在正确机械姿态下重新建立零位参考。不能用它把任意事故姿态直接定义为机械原点。
3. **主控读数补丁**：历史上用PDO交换修正主控取数对象；它不是机械回原点，也不能替代标零。

## 1. 用户本次现场经验（2026-11-06）

触发情形：严重运动异常后红灯报警，上电状态不能恢复；机械臂未回原点就断电重启；再次上电使能时出现先上抬、后下坠。

用户报告的恢复顺序为：

> 使用V1.3.4-stable目录中的RobotMaintenanceTools.exe，把伺服刷到3.4.5.1以上 → 重启后不再下坠 → 用DobotStudio将六轴运动回原点 → 刷回3.1.5.0 → 使用工作空间标零脚本完成软件标零。

用户还报告：当前使用场景中DobotStudio自身标零选项无效；3.1.5.0使用文件名为 `CR5_Servo_ST_FOE_V3.1.5.0_UNVERIFIED.bin`；每次正常下电前应返回原点，否则可能再次出现上述异常。

这些是用户对本机的经验，不是本次重新完成的实机验证。**“3.4.5.1以上”没有在本次找到的归零材料中得到对应包和兼容性验证，不能据此任意选择更高固件。** RobotMaintenanceTools.exe及该高版本包未收集到本目录；原软件目录需另行保留并核对型号、版本和来源。

## 2. 与历史证据怎么衔接

- `历史资料/ZEROING_SOP.md`：包含9月、10月及11月3日追加记录。原版主控下标零成功，再恢复六轴补丁；使能后静止至少30秒再标，历史成功最大偏差约0.0116°/0.0119°。
- `历史资料/ZERO_RECOVERY_RUNBOOK.md`、`ALARM_086_FINDING.md`：解释0x86上使能位置差异报警。历史代码分析判据为任一轴两套位置差大于5°后强制下使能；记录过掉使能时下坠。它支持“坐标参考不一致与掉使能有关”，不能单凭现象断言每次都是同一个根因。
- `历史资料/flash_32d8_baseline.md`：3.2.d.8历史基线下未复现报警后使能下坠/晃动，也明确提醒重标零前禁用旧点位。它**不证明3.4.5.1的版本号或所有更高版本都兼容**。
- 较早runbook曾说零点掉电保持，后来的SOP要求断电复验，本次用户又报告异常断电后复发。故不能写“永久修复”或“任何断电都保持”。
- 历史SOP记录过示教器/DobotStudio标零成功，本次用户报告当前界面方式无效。保留差异，当前接手优先核对原版/补丁、使能状态和新鲜日志，不能把“界面必然有效/必然无效”推广到所有版本。

## 3. 接手处理顺序与检查点

### A. 异常发生后先留证并停止反复使能

保留报警码、故障日志、六轴读数、物理姿态照片、固件版本、Application.app哈希及本次断电过程。历史上每次“使能后被报警下使能”都可能继续下坠，不能反复试使能来验证。发生过严重碰撞或下坠时，先由现场人员确认机械、抱闸及支撑状态可进行恢复。

普通IO板红灯与本节的异常抬臂/下坠应分开记录。README另记过IO报警整柜断电后恢复，但不能把所有红灯都当作只需重启。

### B. 先恢复可控状态，再机械回原点

由现场维护人员核实可用固件和维护工具后执行用户描述的临时固件切换。不得把历史3.2.D.8材料直接改称3.4.5.1，也不得在未知固件下直接运行旧轨迹回零。

确认恢复可控后，用DobotStudio逐轴、低速回到正确机械零位，核对刻线/姿态；此步骤完成前不做“把当前姿态设为零”的软件标定。不用旧存点代替机械对齐。

### C. 回到3.1.5.0后，按本机主控条件软件标零

历史适用流程：

`刷回3.1.5.0 → 整柜断电使固件生效 → 备份并回退原版主控 → 重启 → 再核对机械对齐与驱动无故障 → 现场确认使能 → 完全静止≥30秒 → 标零 → 查新鲜日志 → 恢复六轴补丁 → 重启 → 验收`

这是历史流程摘要，**不是一键执行授权或保证无运动的程序**。不要机械累计重启次数；固件、原版主控、补丁每次变更都要分别确认生效。

历史应用识别值：

| 应用 | Application.app MD5 | 用途 |
|---|---|---|
| 原版 | 8416cf0eee070a640702c077eb904b4e | 历史标零前提 |
| 六轴swap补丁 | 9a808cd9dd8f3aa6adaa4de1a34eb9b3 | 历史标零后运行配置 |

Application.app与Application.crc必须配对。安装前核查具体控制器基线；不要把这里的文件装到不同主控版本。恢复备份时选择**明确的单一备份目录**，不要照抄旧SOP的BACKUP_patch_*通配符覆盖命令。

### D. 用结果验收，不能只看界面提示

| 观察 | 含义/下一步 |
|---|---|
| 新日志HomeNumdone 0→2→4→6，并出现servo calihome done | 历史标零完成依据，仍需关节/姿态复验 |
| 停在0 | 优先查未使能、重启后controlMode=0、客户端未重连 |
| 停在2 | 查是否补丁版及各轴驱动故障；不是唯一根因判据 |
| HTTP status=false | 状态不满足，不能算标零成功 |
| 0x603F非0、0x8612等 | 驱动故障；clearAlarms不保证驱动故障已清 |
| innerEncoder全0 | 较新SOP明确不能单凭此值判失败 |

最终核对：六轴与真实机械姿态一致、近零误差符合本机实际精度、无新报警；下/上使能及必要断电后的复验由现场人员在可控条件下进行。**下坠曾出现时不能把“再次使能”当无风险验收。** 正常下电前按用户经验先回原点；事故时若无法安全回原点，先停机处置，不为满足“回零”强行运动。

恢复后旧点位、TCP、参考系、模型与轨迹均需复验；本目录不认证11月5日或任何旧轨迹可直接实机运行。
