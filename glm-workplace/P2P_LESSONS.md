## 1. ⛔ 两次碰撞事故（同一个病根，两次都撞在圆柱上）

### 事故 A —— v14l（2026-10-12 11:30）：**无补偿直发驱动 MOVL**

```
改动：短直线段（≤150mm）跳过细分途经点、直接让驱动器走直线
结果：P5 直发后停在 4/17
      · 法兰位姿 = 命令的 TCP 目标位姿（差仅 5.5mm）✓ 看起来"对"
      · 但【真实尖端多探出一个工具长 159.63mm】
      · 停在 (103.4,-929.8,300.4)，【距圆柱轴 106.7 < R180】⇒ 进入圆柱包络 ✗
```

**⇒ 死因（一字不改地引用）**：
> 驱动 MOVL **无工具补偿** —— 驱动把 TCP 坐标当**法兰**目标执行，落到完全不同构型。
> **碰撞预检背书的是【意图】（命令 TCP 直线安全），验证不了【执行语义】（驱动按法兰目标走）。**

### 事故 B —— v14m（2026-10-12 17:00）：**细分步长 20 → 40mm**

```
结果：RoboDK 界面内机械臂与圆柱碰撞显示、运动停止（GUI 心跳 17:00:08 / 日志 17:00:09 同时停更）
机理：40mm 跳的 MoveJ【弦路径】偏离认证直线
      真实表面裕度只有 ~19.9mm（轴线距 199.9mm − 半径 R180）
      v14m 落地时误把【轴线距】当成了【裕度】（算术错误，已认领）
盲区：离线 verify 只验「途经点在认证直线上」，【验不到「MoveJ 弦扫掠包络」】
```

### 事故 C —— 2026-10-13（用户本次报告）：**避碰段直发**

```
现象：勾选"法兰补偿MOVL"（v14p 系）跑到 P9 后，界面里【末端与磨砂圆柱碰撞】
病根：P9 的 p2p_note = 'MoveJ弧碰退回MoveL细分'
      ⇒ 该段本来就是因为「MoveJ 弧会撞磨砂圆柱」才改走直线细分的
      ⇒ 而"法兰补偿直发"把那条直线交给驱动器自己走 ⇒ 与事故 A 完全同源
```

**★★★ 关键认知（这一条最贵）**：
> **"直发失败再自动回退细分路径"**救不了碰撞**✗** ——
> 因为**碰撞发生在回退【之前】**，回退的起点**已经被直发带偏**，
> 细分路径从**错误的起点**出发，**同样会撞**。
> ⇒ **正解只有一个：不让避碰段直发**（或干脆不勾选该开关）。
