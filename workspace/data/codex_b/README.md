## 2. 复核结果（本会话用 codex 的 pcap 重新算过）

### 2.1 抓包确为 EtherCAT

```
linktype = 1 (Ethernet)   ethertype = 0x88a4 (EtherCAT)
zero32_calibration.pcap : 73042 帧，其中 1111 字节周期帧 72994 个
capture315_ethercat.pcap0/.pcap1 : 85686 帧，同样以 1111 字节帧为主
```

### 2.2 ✅ 证实：`innerEncoder` 是 PDO 里持续流动的字段，标定只是"快照"

在 1111 字节帧的固定偏移 `603/660/717/810/879/950` 读 int32：

| 抓包 | 与 `homeEncoder.json` 的关系 |
|---|---|
| `zero32_calibration.pcap` | 元组 `[598234, -192592, -580282, 389348, -718959, 576819]` 出现 **1690 次**，与 JSON 记录**逐位相同** |

再做时间切分：该元组在标定请求（`15:45:15.448`）**之前**已出现 **1636 次**（最早 `15:45:12.177`），之后只有 **56 次**。
⇒ **不是"回零后读回一个结果"，而是"把一个一直在流的实时字段抄了下来"。**

### 2.3 ✅ 证实：3.1.5.0 上控制器用的是「零偏置 = 0」

`capture315_ethercat.pcap1` 里 PDO 元组 = `[45877, -57977, 19080, -12807, -42461, -18502]`；
`capture315_exchange_after.json` 里重新使能后的关节值 = `[-8.176508, 10.333052, 3.400566, 2.282550, 7.567685, 3.297551]`。

用 `scale = 360/(20000×101)` 对账：

| 轴 | PDO 计数 | × scale | 实测关节值 | Δ(°) |
|---|---|---|---|---|
| J1 | 45877 | -8.176099 | -8.176508 | 0.000409 |
| J2 | -57977 | 10.332535 | 10.333052 | 0.000517 |
| J3 | 19080 | 3.400396 | 3.400566 | 0.000170 |
| J4 | -12807 | 2.282436 | 2.282550 | 0.000114 |
| J5 | -42461 | 7.567307 | 7.567685 | 0.000378 |
| J6 | -18502 | 3.297386 | 3.297551 | 0.000165 |

**六轴全部吻合到 0.0005° 以内（≈0.00015 圈电机）**，且符号与已知方向约定一致（只有 J3 是 `inverted:false`）。
⇒ **3.1.5.0 上"关节值 = 编码器绝对计数 × scale"，也就是零偏置被当成了 0。**
残差 0.0005° 对应 PDO 值在 3 秒窗口内的 ±5 计数抖动，属正常。

### 2.4 ✅ 证实：标定**没有**改变伺服上报的位置

按时间切分 3.1.5 的抓包：

| 窗口 | PDO 元组 |
|---|---|
| 上使能前（1112 帧） | `[-603293, 202704, 585171, -394376, 709124, -566921]`（陈旧，不刷新） |
| 上使能后、标定前（4044 帧） | `[45882, -59041, ...]`（实时） |
| 标定后（23718 帧） | `[45877, -57977, ...]`（几乎没变） |

⇒ **归零完全发生在控制器侧**：控制器把"当前编码器计数"记为偏置，之后用它做减法。

> ⛔ **2026-09-24 更正（`SERVO_SUMMARY.md` §3.6 数值证伪）**：上面这句"之后用它做减法"
> **只对"控制器内部"成立，不能推广到 `homeEncoder.json` 的 `innerEncoder`**。
> 以同一组数据对照两种模型：减法模型残差恒为 **≈0.45° = ±2506 counts × scale = `innerEncoder` 自身量级**，
> 无偏置模型残差 **0.0005°**。
> ⇒ **`innerEncoder` 不参与关节角运算**，它只是标定时刻 `0x6064` 的一份记录。
> 另有独立反证：若真做减法，六轴关节角会**同时**偏 0.45°，而实测六轴吻合到 0.0005°。

### 2.5 ⚠️ 一处必须澄清的误读风险

`sdo_structured_audit.json` 里有对 `0x607C` 的 SDO 写、目标站 1003–1008。
其时间戳换算约在 **2026-09-22 18:20 前后**，对应 `sdo_trace_now.pcap`（18:29）——
那是 **codex 自己的 `ecat_zero` 工具发的**，**不是控制器发的**。
⇒ 不能据此推翻「控制器从不写 `0x607C`」这一结论（我们 §20.2 的抓取仍然成立）。
