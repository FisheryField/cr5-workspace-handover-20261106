# J2「稳态误差过大」（报警 249）现场事件分析

时间：2026-09-26 09:30（控制器时间，CST）
现场：用户在 RoboDK 的新工位里跑「TCP 法兰真实运动」脚本；先做了一段 TCP 笛卡尔真实运动，
随后下发「关节全部回零」（`JointMovJ(0,0,0,0,0,0)`），机械臂立即报错。
结论：**报警 = id 249「第二轴稳态误差过大」**，判据是 J2 的**位置差 0.120079° > 阈值 0.05°**；
其余五轴都在阈值内（0.0003~0.0089°）。报警后控制器自动下使能，那条回零命令**没有被执行**。

## 2. 机制（证据等级：【逐条读码】+【现场实测数值】）

1. 3.1.5.0 驱动器把**真实位置**放在 `0x6064`，把`0x6062`（位置给定）在使能后塞成编码器原始计数 —— 这正是当初零点错乱的根因。
2. 我们的补丁把该轴 TxPDO 的**最后一项**换成 `0x6064` ⇒ 主控上报的关节角变正确（零点修复成功，9/25 实测六轴 ≈0）。
3. 副作用：主控的**稳态误差检查**读的是同一路数值 ⇒ 现在它比较的是"主控给定位置 vs 驱动器实际位置"，
   也就是**驱动器真实的静态跟随误差**。
4. J2 是承载整条手臂重力的轴，在"手臂外伸"的姿态（J2=39.6°, J3=-33.4°, J5=-65.6°）下静差 ~0.12°；
   其余五轴 ≤0.009°。厂商的容忍度 0.05° 是**按"给定比给定"设计的**（那种比较恒为 0），
   所以这个阈值在当前补丁下变得过严。
5. 保留日志里唯一另一处 `SteadyError isErr:0`（9/25 19:28，`log.4`）说明：**带载小的姿态下这项检查是能过的**，
   ⇒ 0.12° 是随姿态/负载变化的**真实物理量**，不是常数偏置。

**未证实的部分（诚实标注）**：日志标签写死为 `(PDO0x6062)`，我**没能**从 SDO 直接读到
`0x6062`/`0x6064` 的实时值做"哪一路是 0.12°"的直接对证（SDO 读全部 `sdo read fail`，
`amrd` 扫 `0x73000000` 那块也不是活的输入映像）⇒ 第 3 条是**强推断**（数值、标签、映射三者自洽），
不是逐条读码。

## 3. 处置选项

| # | 做法 | 评价 |
|---|---|---|
| a | **清报警**（示教器"清除报警" / `ClearError` / `POST /interface/clearAlarms`） | 立刻恢复可用；但**下一次带载姿态的动作结束还会再报**（0.12° > 0.05° 稳定存在） |
| b | **放宽 `SteadyErrorThreshold`**（`AdvancedFunction.json`，每轴一个数；例如 J2 设 0.2~0.3）→ 重启控制器生效 | **最小、可逆、对症**。副作用：动作"到位"的接受判据放宽到 0.2~0.3°（≈2~3 mm @600mm 半径） |
| c | 降低 J2 真实静差（伺服位置环增益/机械检查） | 治本但属于伺服调参，风险高、无厂商支持 |
| d | 回退 PDO 补丁（改回 0x6062） | 报警消失，但**零点错乱复现** ⇒ 不可取 |

**推荐**：先 (a) 恢复可用；若再报就用 (b) 把 J2（必要时全轴）阈值放到物理上合理的值。
0.12° @J2 ≈ 600 mm 半径处约 **1.3 mm** 的位置偏差 —— 是个真实存在的量，后续若明显变大，
说明 J2 伺服/机械在退化，值得单独跟踪。

### 6.3 结论与机制

* **J2 驱动器无法建立/维持转矩**：一上使能，J2 伺服立刻报 `33921 速度偏差过大保护`
  （"给定速度与实际速度偏差超范围"），控制器随即下使能。报警 99（关节2轴状态错误）、
  134（上使能关节位置偏差过大）都是**后果**，不是原因 —— 重启后基准已同步到实际位置，
  但仍在使能瞬间复现。
* **"下沉"只发生在使能窗口内**：下使能时抱闸抱住（角度不再变），
  一旦上使能、抱闸释放而转矩又建立不起来，重力就把手臂拉下去 —— 每次尝试掉 ~11~12°：
  `39.59 →(09:50 那次)→ 50.23 → 61.53 →(10:14 这次)→ 73.68`。
* 与前面几条症状自洽：J2 静差 0.12°（其余 ≤0.009°）是**最早出现的退化征兆**。

### 6.4 建议的硬件排查（按性价比）

1. **先机械托住/垫住手臂** —— 现在 J2=73.7°，再来一次使能还会掉 ~12°，可能撞台面/夹具。
2. 柜内**把 J2 与另一轴（例如 J3）的驱动卡对调**：
   * 故障跟着卡走 ⇒ 驱动卡坏；
   * 故障留在 J2 ⇒ J2 电机 / 动力线(U·V·W) / 编码器线 / 抱闸线。
3. 检查 J2 的动力与编码器插头（松动、氧化、断针）。
4. 厂商参数故障复位 `H0C.00`(`0x200C:01`) 写 1：可以做，但预期 35 ms 内复现；
   建议**托住手臂之后**再试一次，观察故障码是否变化。
5. 确认是硬件后，在无厂商支持的前提下只能换件/换轴。

## 7. J2 故障与"零点修复"的因果关系（2026-09-26 10:18 追加核查）

### 7.1 新增证据：六轴固件版本一致（排除"J2 刷坏/刷失败"）

`0x5000:07` 只读 SDO（HTTP :22000 → 日志 `readSDO` 行；`sdo read fail` 是厂商文案 bug，`value=` 才是值）：

```
slave=3..8（J1..J6）  value=12624 = 0x3150 = 3.1.5.0   ← 六轴完全一致
```

⇒ J2 的固件与其他五轴**逐位一致**，不存在"只有 J2 刷坏"。补丁后的 PDO 表也六轴同构
（各轴 `1A00` 末项都是 `16#60640020`、第 3 项都是 `16#60620020`）。

### 7.2 为什么"补丁直接弄坏 J2"在机制上不成立

* 那 2 字节改的是 **TxPDO（驱动器→主控）** 的一项：主控"用哪个对象当关节角"。
  **RxPDO（主控→驱动器：`0x6040` 控制字 / `0x607A` 目标位置 / `0x60FF` 速度 / `0x60B2` 转矩偏置…）
  一个字节都没动**（本次启动日志的 1600 映射与补丁前逐项一致）。
* J2 报的 `33921 速度偏差过大保护` 是**驱动器内部**的保护（给定速度 vs 实际速度偏差超范围）
  ⇒ 属于电机/动力线/编码器/抱闸/功率级范畴，主控"读哪个位置对象"改变不了它。
* **同一套操作做了六遍，只有 J2 坏**：补丁（六轴）、固件（六轴，刚核实一致）、重新标零（六轴）、
  阈值（只动 J2 的**容差**，且在故障**之后**才改）。⇒ 指向该轴的硬件。
* 时间顺序：J2 的第一个异常（0.12° 静差）出现在 09:30 那次**正常运动结束**时；
  J2 伺服故障首次出现 09:50:37（上使能时驱动器自报）；我的阈值修改（10:08）与重启（10:09）都在其后。

### 7.3 必须诚实标注的两点（不能宣称 100% 无关）

## 8. 三条报错能榨出的信息（2026-09-26，报警表逐条比对）

现场控制软件报的三条：**关节2轴状态错误（99）**、**上使能关节位置偏差过大（134）**、**速度偏差过大保护（33921）**。

### 8.1 三条的层级：只有一条是根因信号

| 码 | 谁报的 | 语义 | 性质 |
|---|---|---|---|
| **33921** | **DS121 驱动器**（`alarm_servo.json`，level 0） | "给定速度与实际速度偏差超范围"；厂商处置：检查硬件/重启/联系技术支持 | **根因信号** |

### 8.2 合起来能确定的事实

* **轴**：只有 J2（99 与 `logServoError ... servo2` 都点名；其余五轴无任何报警）。
* **时机**：`10:14:04.353 robot enabled` → `10:14:04.388 g_isErr:1` = **35 ms** ⇒ 瞬时，不是热/过载类（那类要几百 ms~秒）。
* **性质**：驱动器要让电机跟速度、但跟不上；而手臂**真的掉了 12°** ⇒ **使能瞬间电机没有输出转矩，轴近似自由落体**。
* **抱闸是好的**：下使能期间角度不再变化（抱闸抱住），只在使能窗口掉 ⇒ 抱闸能松能紧。
* **编码器是好的**：能报出 0.12° 级跟随误差、能报"速度偏差"、位置读数连续。

### 8.3 最有价值的部分：**哪些保护没有报**（`alarm_servo.json` 共 87 条）

| 保护族 | 表里的码 | 本次是否报 | 排除/指向 |
|---|---|---|---|
| 电机堵转 | 28961 | ✗ | 不是机械卡死（卡死会堵转/过载） |
| 电机过载 | 29056 | ✗ | 同上 |
| 软件过流 | 8992 | ✗ | 不是短路（短路会立刻过流） |

⇒ 排除：机械卡死、短路、抱闸、编码器、通讯、电源、过温。
⇒ 剩下最像：**驱动器→电机这一段"没有电流/没有转矩"** —— 典型是**动力回路缺相**
（电机线／柜内插头／驱动卡输出级），也可能是驱动卡功率级坏或电机绕组开路。
缺相在永磁同步电机上正好表现为"没转矩、电流小、速度跟不上"，且**不会**触发过流。

### 8.4 可做的定位动作（按性价比，均不需上使能）

1. **断电，量 J2 电机三相绕组电阻**（柜内 J2 驱动卡输出端或拔下电机插头）：
   U-V / V-W / W-U 应与 J3 相当且三相接近；某一相∞ = 断线/插头氧化/绕组开路；某相明显偏低 = 短路。
2. **看 J2 驱动卡 LED**（ERR/RUN 状态、有无闪烁码）。
3. **J2 ↔ J3 驱动卡对调**：故障跟着卡走 = 卡坏；留在 J2 = 电机/线束。
4. 托住手臂后再做一次上使能 + `H0C.00` 复位，看码是否变化（若变成 8992 过流或 28961 堵转，方向完全不同）。

### 8.5 能力边界

* 驱动器更细的故障码（`0x603F` 等）**读不到**：SDO 读一律被驱动器拒绝（日志 `sdo read fail`），
  只能拿到 `GetErrorID()` 里的 33921。
* 驱动器内部瞬时电流/速度值没有对外接口。

### 8.6 安全结论

只要该故障存在，**每次上使能都会让手臂掉约 12°**（抱闸松开、转矩建立不起来）。
⇒ **托住手臂/排除故障之前不要再上使能**。当前 J2 = 73.7°，再掉两次可能撞台面/夹具。
